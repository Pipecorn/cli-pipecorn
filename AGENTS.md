# AGENTS.md

Instructions for AI coding agents (Claude Code, Codex, Cursor, Copilot) working in this repository. `CLAUDE.md` only points here.

This repo is two things:

1. **`@pipecorn/cli`**, the `pipecorn` command-line interface to the Pipecorn REST API (`https://app.pipecorn.com/api/v2`). TypeScript, built on oclif.
2. **The Pipecorn Agent Plugin** ([agent-plugins.org](https://agent-plugins.org/specification)): `plugin.json`, `mcp.json` and `skills/pipecorn/SKILL.md` at the root. It gives an agent the Pipecorn MCP server and the rules for using it. None of these files ship in the npm package (`files` in `package.json`).

If you are an agent that wants to *use* Pipecorn rather than change this code, read [`skills/pipecorn/SKILL.md`](skills/pipecorn/SKILL.md), then <https://pipecorn.com/auth.md> for authentication and <https://pipecorn.com/openapi.json> for the API.

## Commands

```sh
npm ci                 # install (Node 20 or 22)
npm run lint           # eslint src test
npm run typecheck      # tsc --noEmit
npm test               # vitest run
npm run build          # tsc -p tsconfig.build.json
npm run dev -- <args>  # run the CLI from source, e.g. npm run dev -- credits
npm run check:schemas  # compare src/api/endpoints.ts with the pipecorn-api-doc checkout
```

CI (`.github/workflows/ci.yml`) runs lint, typecheck, test and build on Node 20 and 22 for every pull request. Run the same four before you push.

## Layout

| Path | What lives there |
| --- | --- |
| `src/commands/` | One oclif command per file. `leads/search.ts` is `pipecorn leads search`. |
| `src/lib/base-command.ts` | `PipecornCommand`: the global flags (`--api-key`, `--format`, `--quiet`, `-o`), output, and error handling. Every command extends it. |
| `src/api/endpoints.ts` | Every API call the CLI makes, grouped by resource. Commands call these, never `fetch` directly. |
| `src/api/schemas.ts` | zod schemas that validate request bodies before they're sent, and the enum values they accept. A zod error exits with code 2. |
| `src/api/errors.ts` | Typed API errors and `exitCodeFor()`, which maps them to exit codes. |
| `src/output/format.ts` | `json`, `csv` and `table` rendering. |
| `test/` | vitest, with `msw` mocking the API: the client and its errors, the schemas, credentials, output formats. |

## Conventions

- **Exit codes are a contract** that scripts and agents branch on: 0 success, 1 API error, 2 invalid input, 3 authentication, 4 rate limit, 5 credits or plan limit. A new error type goes through `exitCodeFor()`. Never exit with a new code.
- **Output.** `json` by default when stdout isn't a TTY, `table` on a TTY. Data goes to stdout, messages and errors to stderr, so pipes stay clean.
- **A new endpoint** goes in `src/api/endpoints.ts` first, then a command in `src/commands/`, then a test with an msw handler. `npm run check:schemas` fails when pipecorn-api-doc documents a path the CLI doesn't call: add the command, or list the path in `KNOWN_UNSUPPORTED` with the reason.
- **Credits.** An email costs 3 enrichment credits and a mobile 30. `contacts enrich` has `--dry-run` to show the cost of a batch before spending it; give any new bulk spending command the same flag.
- **README.** The "Commands" section is generated by `npm run docs` (`oclif readme`) from the command classes. Edit the command's `description` and flags, not the README.
- **Secrets.** The API key comes from `--api-key`, `PIPECORN_API_KEY` or `~/.config/pipecorn/credentials.json` (mode 0600), in that order. Never log it, never put it in a test fixture or an error message.

## Releasing

Pushing a `v*` tag runs `.github/workflows/release.yml`: npm publish with provenance, tarballs on the GitHub release, then the Homebrew cask. Bump `version` in `package.json` in the same pull request as the change; a maintainer tags it. Never tag or publish yourself.

## The Agent Plugin

- `plugin.json` must validate against `https://agent-plugins.org/schemas/1.0.0/plugin.schema.json`, and `mcp.json` against `.../mcp.schema.json`.
- `mcp.json` points at the hosted server, `https://mcp.pipecorn.com/mcp`. It must never carry an API key: clients sign in with OAuth or add their own `X-API-Key` header.
- `skills/pipecorn/SKILL.md` is the same skill pipecorn.com serves at `/.well-known/agent-skills/pipecorn/SKILL.md` (source: `lib/agent/docs.ts` in the website repo). Change both together.
- The MCP server is listed in the official MCP registry as [`com.pipecorn/mcp`](https://registry.modelcontextprotocol.io/v0/servers/com.pipecorn%2Fmcp/versions/latest).
